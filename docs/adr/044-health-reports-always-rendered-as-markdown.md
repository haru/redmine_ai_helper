# ADR-044: Health Reports Are Always Rendered and Edited as Markdown

**Date**: 2026-10-03
**Status**: Accepted

## Context

Health reports are generated by the LLM as Markdown. Until now the stored
report was rendered with `textilizable`, which follows the site-wide "Text
formatting" setting, so on Textile sites Markdown headings and emphasis were
not rendered correctly. The new edit feature (spec 064) adds an editing
toolbar and a preview, both of which also depend on the text formatting
setting in Redmine core (`wikitoolbar_for`, `preview_text_path`).

## Decision

- Stored health reports are rendered with `render_health_report_markdown`
  (`md_to_html` + issue-reference linkification), independent of
  `Setting.text_formatting`.
- The edit toolbar loads the CommonMark jsToolbar assets directly through
  `ai_helper_markdown_toolbar_heads` instead of `wikitoolbar_for`, so the
  Textile toolbar is never used for reports.
- The preview is served by a dedicated endpoint
  (`health_report_preview`) that uses the same renderer.

## Consequences

- Reports look the same on every site and the preview matches the saved
  result exactly.
- On Textile sites, reports saved earlier are now rendered as Markdown. This
  matches how they were generated, so existing display improves rather than
  regresses.
- Textile-specific syntax typed by an editor is not interpreted.
