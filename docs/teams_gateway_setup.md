# Microsoft Teams Gateway Setup Guide

This guide explains how to connect the Redmine AI Helper to Microsoft Teams so
users can ask questions in a team channel or in a one-to-one chat with the bot
and receive the answer in the same conversation.

Unlike Slack and Discord, Teams offers **no outgoing connection**: the Bot
Framework delivers every activity to a URL you register. Your Redmine server
must therefore be reachable from the internet over **HTTPS**, and the receiving
endpoint is part of the Redmine web application:

```
https://<your-redmine-host>/ai_helper/chat_webhook/teams
```

Answers are still generated by the resident gateway process, exactly as for the
other chat tools.

## Requirements

- A public **HTTPS** URL for your Redmine server. For local development, expose
  it through a tunnel (`dev tunnels`, `ngrok`, …) and register the tunnel URL.
- An Azure subscription that may create an **Azure Bot** resource.
- A Microsoft 365 tenant that allows **custom app upload** to Teams.
- A dedicated Redmine **service account** (e.g. a user named `ai_helper`) that
  the gateway runs as. Add it to the relevant projects with an appropriate
  role — every question from Teams is answered with **this account's
  permissions**, regardless of who asks.

## 1. Create the Azure Bot

1. In the Azure portal, create an **Azure Bot** resource. For **Type of App**,
   choose **Single Tenant**. (Microsoft stopped registering multi-tenant bots on
   July 31, 2025, and the portal no longer offers that type. This integration
   supports single-tenant bots only.)
2. Copy the **Microsoft App ID** of the bot. This is the value Redmine stores
   as the **App Token**.
3. Open the bot's app registration and create a new **Client secret**. Copy the
   secret **value** immediately — it is shown only once. This is the value
   Redmine stores as the **Bot Token**.
4. In **Configuration**, set the **Messaging endpoint** to
   `https://<your-redmine-host>/ai_helper/chat_webhook/teams`.
5. In **Channels**, add the **Microsoft Teams** channel.

## 2. Find the directory (tenant) ID

In the Microsoft Entra admin center, open **Overview** for your organization
and copy the **Directory (tenant) ID** (a GUID). This is the value Redmine
stores as the **Tenant ID**.

This identifier is used twice, so a wrong value breaks the integration in two
different ways:

- **Incoming**: Redmine accepts activities from this organization only. A Bot
  Framework signature proves the request comes from Microsoft, not which
  organization it came from, so this identifier is what keeps another
  organization from using your integration.
- **Outgoing**: a single-tenant bot's credentials exist only in its own
  directory, so this is also the tenant Redmine requests its Bot Connector and
  Microsoft Graph access tokens from. A wrong tenant makes every reply fail
  with a credential error.

## 3. Build the Teams app package

Create a Teams app manifest (schema v1.12 or later) containing at least:

```json
{
  "bots": [
    {
      "botId": "<Microsoft App ID>",
      "scopes": ["personal", "team"],
      "supportsFiles": false,
      "isNotificationOnly": false
    }
  ],
  "webApplicationInfo": {
    "id": "<Microsoft App ID>",
    "resource": "https://AnyString"
  }
}
```

To let the bot read the messages around a question (see step 6), also declare
the resource-specific consent (RSC) permission:

```json
"authorization": {
  "permissions": {
    "resourceSpecific": [
      { "type": "Application", "name": "ChannelMessage.Read.Group" }
    ]
  }
}
```

Zip the manifest together with its icons and upload it:

- **Team channel use**: in the target team, choose **Manage team → Apps →
  Upload a custom app**. This upload is what grants the RSC permission for that
  team; no tenant-wide administrator consent is needed.
- **One-to-one chat use**: add the same app in the personal scope.

## 4. Configure Redmine

1. Go to **Administration → AI Helper → Chat integrations** tab.
2. In the **Microsoft Teams** section, check **Enable** and fill in:
   - **App Token** — the Microsoft App ID from step 1.
   - **Bot Token** — the client secret from step 1.
   - **Tenant ID** — the directory (tenant) ID from step 2.
   - **Execution account** — the Redmine service account all Teams questions
     run as. Speakers are **not** mapped to individual Redmine users.
   - **Default project** — the context for one-to-one chats and for channels
     that have no binding.
3. Save. The **Webhook URL** shown in this section is the messaging endpoint
   registered in step 1.4; confirm the two match.
4. Under **Channel bindings**, map each Teams channel to a Redmine project.
   To get a channel ID, open the channel in Teams, choose **⋯ → Get link to
   channel**, and take the `threadId` parameter of the URL — it looks like
   `19:xxxxxxxx@thread.tacv2`. The project must have the **AI Helper** module
   enabled.

Channels without a binding, and one-to-one chats, are answered in the default
project's context.

## 5. Run the gateway

The gateway is a resident process, separate from the Redmine web server, and it
runs every enabled adapter:

```bash
cd /path/to/redmine
bundle exec rake redmine:plugins:ai_helper:chat_channel:gateway RAILS_ENV=production
```

`log/ai_helper.log` lists the adapters it started. Received activities are
stored by the web process and picked up by the gateway within a few seconds, so
both processes must run for Teams to be answered.

## 6. Use it

- **In a team channel**: mention the bot (`@AI Helper how many open issues?`).
  The answer is posted as a reply in the same thread. Continue by mentioning
  the bot again in that thread.
- **In a one-to-one chat**: just send your question — no mention needed. The
  conversation continues until 24 hours pass without a message; the next
  question after that starts a fresh conversation.
- Issue references are posted as markdown links, and answers longer than 6,000
  characters are split across several messages with no content lost.
- With the RSC permission granted, the bot also reads the surrounding messages
  of the channel or thread so it can answer questions that refer to them. One-
  to-one chats have no surrounding messages to read, so nothing is retrieved
  there.

## Troubleshooting

### Teams shows an error and Redmine logs a verification failure

```
ai_helper_chat_webhook: request verification failed for channel_type=teams
```

The activity did not pass Bot Framework verification, or it came from another
organization. Check that:

- the **App Token** is the bot's Microsoft App ID (the JWT is issued for it),
- the **Tenant ID** matches the organization the app is installed in,
- the messaging endpoint points at this Redmine instance over HTTPS.

The HTTP response never states the reason; the log line above, together with
the adapter's own warning, names it.

### The bot receives nothing at all

The endpoint answers `404` when the Teams integration is disabled or its
required fields are incomplete, which looks the same from the outside as an
unknown URL. Re-check step 4, then confirm the messaging endpoint is reachable
from the internet (`curl -i https://<host>/ai_helper/chat_webhook/teams`
returns `401`, not a connection error — the endpoint rejects unsigned requests).

### The answer is prefixed with "The recent messages … could not be retrieved"

The Microsoft Graph request for the surrounding messages failed. The reason is
logged with a backtrace:

```bash
grep "could not import the conversation context" log/ai_helper.log
```

Common causes:

- **The RSC permission was not granted.** The declaration must be in the
  manifest *before* the app is uploaded to the team; adding it afterwards
  requires uploading the updated package to that team again. Graph answers
  `403` until then.
- **Protected API restrictions.** Microsoft classifies the channel message APIs
  as protected, and some tenants reject them even with RSC granted. The bot
  keeps answering — only the surrounding context is missing.

### The gateway stops answering Teams questions

```
gateway: adapter teams terminated (configuration/credential error)
```

The client secret expired or was rejected, or the **Tenant ID** is not the
directory the bot is registered in — a single-tenant bot's token request is
rejected by any other tenant. Credential errors are never retried; create a new
secret (step 1.3) or correct the Tenant ID (step 2), then start the gateway
again. Other enabled chat tools keep running.
